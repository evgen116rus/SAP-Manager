# SAP Manager

Оконная программа для Windows (C++, Win32) для установки, проверки и удаления **SAP GUI 7.70** и компонентов **SAP Crypto** на удалённых компьютерах. Все удалённые команды выполняются через `pse.exe` (переименованный PsExec) с ключом `-r ps_sap`.

## Возможности

- Установка на удалённый ПК с **выбором компонентов**:
  1. SAP GUI 7.70
  2. PDF Print GUI
  3. Business Explorer (BE / SapBI)
  4. SAP Secure Login Client
  5. SAP Crypto (`sapcrypto.dll`, `sapgenpse.exe`, `slcryptokernel.dll`, `ssfrfc.ini`)
  6. `set_xml_path.reg` (пути XML), применяется к реестру вошедшего пользователя
  7. Настройки SAP Logon (reg) для вошедшего пользователя
- Проверка, установлен ли SAP GUI (наличие и версия `saplogon.exe`, наличие деинсталлятора).
- Проверка компонентов SAP Crypto: на месте / отсутствует / отличается по размеру от эталона. При необходимости копирование.
- Применение reg-файла в реестр **вошедшего пользователя** удалённого ПК, а не того, от чьего имени запущена программа.
- Автоматический перевод службы «Удалённый реестр» в режим «Автоматически» и её запуск.
- Удаление SAP GUI и остаточных каталогов.
- Вывод ответа `pse.exe` и всех шагов в журнал внизу окна. Операции идут в фоне, окно не зависает.

## Требования

- Windows, права администратора на удалённом ПК.
- `pse.exe` (PsExec) рядом с программой или в `PATH`.
- Доступ к админ-шаре `\\ПК\C$` и открытый SMB/RPC на удалённом ПК.
- Доступ к сетевым дистрибутивам (см. «Настройки»).
- Файлы `saplogon_options.reg` (и при желании `saplogon_options_HKCU.reg`) рядом с `sap_manager.exe`. `set_xml_path.reg` берётся из дистрибутива (`SapInstall760\#`), а если он недоступен, то из файла рядом с exe.

## Использование

1. Запустите `sap_manager.exe`.
2. Введите **имя компьютера**.
3. По желанию укажите **учётную запись** (`DOMAIN\user`) и пароль: она используется для подключения к ПК. Процесс на ПК по умолчанию запускается от SYSTEM; флажок «Процесс на ПК от указанной учётки» запускает его от этой учётки (нужно, если дистрибутив недоступен компьютерной учётке, но политика должна разрешать этой учётке вход).
4. Нажмите **«Статус»**: программа покажет разрядность ОС, наличие SAP GUI и версию, состояние Crypto, состояние службы удалённого реестра и вошедших пользователей.
5. Отметьте нужные компоненты и нажмите **«Установить выбранное»**.

Остальные кнопки:

| Кнопка | Действие |
|---|---|
| Удалить SAP | Удаляет SapBI, SAP GUI, PDF Print и SLC через `NwSapSetup.exe`, затем папку `SAP` |
| Crypto: проверить | Проверяет файлы Crypto и предлагает скопировать недостающие |
| Reg пользователю | Применяет `set_xml_path.reg` и `saplogon_options.reg` для вошедшего пользователя |
| Статус | Полная проверка состояния ПК |

Поле **«Пользователь для reg»** (`DOMAIN\user`) необязательно: если оно пустое, вошедший пользователь определяется автоматически. Если сессий несколько, программа спросит, для какой применять настройки.

## Как применяются reg-файлы

Это относится к обоим файлам: `set_xml_path.reg` и `saplogon_options.reg`.

1. Включается служба `RemoteRegistry` (`sc config ... start= auto`, `sc start ...`) через `pse.exe`.
2. Определяется вошедший пользователь и его SID.
3. В копии reg-файла `HKEY_CURRENT_USER` заменяется на `HKEY_USERS\<SID>`; ветки `HKEY_LOCAL_MACHINE` остаются без изменений.
4. Файл копируется на ПК в `C:\Windows\Temp`, импортируется командой `reg import` через `pse.exe` и удаляется.
5. Результат проверяется по наличию ключа `SAPLogon\Settings` в `HKEY_USERS\<SID>`.

Используется `saplogon_options.reg`, а если его нет, то `saplogon_options_HKCU.reg`. Служба удалённого реестра после операции остаётся в режиме «Автоматически». Профиль пользователя должен быть загружен, то есть пользователь должен быть залогинен.

## Настройки

Константы в начале `sap_manager.cpp`:

| Константа | Значение по умолчанию |
|---|---|
| `DIST_ROOT` | `\\ftp\Distrib\Soft\SAP\SapInstall` |
| `SAP770`, `SAP760`, `SLC`, `CRYPTO` | подпапки дистрибутивов относительно `DIST_ROOT` |
| `PSE_SERVICE` | `ps_sap` (имя службы для `pse.exe -r`) |
| `REG_MAIN`, `REG_HKCU` | имена reg-файлов |

После изменения пересоберите программу.

## Сборка (GitHub Actions)

В репозитории должны быть:

```
sap_manager.cpp
saplogon_options.reg
saplogon_options_HKCU.reg
set_xml_path.reg   (необязательно, запасной вариант)
.github/workflows/build.yml
```

Сборка запускается при push в `main`/`master`, по тегу `v*` или вручную (workflow_dispatch). Результат (`sap_manager.exe` и reg-файлы) лежит в Actions → запуск → Artifacts. При push тега `v*` файлы добавляются в Release.

Локальная сборка (Developer Command Prompt for VS):

```
cl /O2 /EHsc /MT /std:c++17 /utf-8 /DUNICODE /D_UNICODE sap_manager.cpp /link /SUBSYSTEM:WINDOWS
```

## Ограничения и замечания

- Без указания учётной записи (режим SYSTEM) установщик на удалённом ПК может не получить доступ к сетевой шаре дистрибутива. В этом случае укажите `DOMAIN\user`. Пароль при этом передаётся в командной строке `pse.exe`.
- Crypto копируется напрямую через админ-шару, а не через `pse.exe`.
- `CheckFileServices.exe` запускается без ожидания завершения.
- Коды возврата `NwSapSetup.exe` (например, `3010` — нужна перезагрузка) выводятся в журнал как предупреждение, установка при этом продолжается.
- `pse.exe` в репозиторий не включён (лицензия Sysinternals), его нужно положить самостоятельно.

## Если «Нет доступа к \\ПК\C$»

Программа выводит код ошибки Windows и подсказку. Частые причины:

| Код | Причина | Что делать |
|---|---|---|
| 5 | Нет прав администратора на ПК | Укажите `DOMAIN\admin` и пароль в окне. Для локальных учёток на ПК вне домена задайте `LocalAccountTokenFilterPolicy=1` |
| 53 | ПК выключен, имя не резолвится, закрыт SMB (TCP 445) | Проверьте ping, попробуйте FQDN или IP, откройте порт 445 в брандмауэре |
| 67 | Админ-шара C$ отключена или не работает служба «Сервер» | Включите службу `LanmanServer` и админ-шары |
| 1326 | Неверный логин или пароль | Проверьте учётные данные |
| 1219 | Уже есть подключение к ПК под другой учёткой | `net use \\ПК /delete` и повторить |

## Ошибка «режим входа не предусмотрен» (1385)

Она возникает, когда процесс запускается от указанной учётки (флажок включён), а политика на ПК запрещает ей такой вход («Запретить локальный вход» и т. п.). Снимите флажок: процесс запустится от SYSTEM, а учётка будет использована только для подключения.
